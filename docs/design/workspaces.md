## 1. 模型

- **主页**：这台电脑上打开着的一组**顶层文件夹**，有顺序，可以是空的。每台设备各一份，不同步。
- **顶层文件夹**：一个文件夹，在侧栏占一节，节标题就是磁盘上的文件夹名（W5，不另存显示名），可以折叠、重命名、移除。每个顶层文件夹一个 `Store`，和现在的文档库一样：真实目录、按标题命名的文件、相对路径链接、`.assets/`。
- **所有顶层文件夹地位平等**。首次启动时引导页新建的那个文件夹只是「最初建的」，之后和别的顶层文件夹没有任何区别：能移除、能挪位置，不是谁的兜底。**每个顶层文件夹自包含**：它自己的元数据、设置（文件夹级）、废纸篓、历史都在它的 `.quiet/` 里；只有和这台机器、这个应用有关的设置放在本机（2.1）。
- **每个顶层文件夹都有 `.quiet/`**（W2，2026-11-22 定）：索引、回收站、历史版本都放在根目录下的 `.quiet/`，和现在的文档库一样，跟着文件夹走。打开已有的文件夹时也在里面建 `.quiet/`，打开时一句话告诉用户（2.5）。所有顶层文件夹的结构、功能完全一样，没有「形态」之分。
- **单个本机文件**：保留在侧栏最下面的「本机文件」节，行为不变（对应 Obsidian 1.14 的「打开 vault 外的文件」）。原来「本机文件」下的文件夹升级成顶层文件夹。

侧栏示意：

```text
主页
置顶                ← 跨文件夹汇总，每项标出所在的顶层文件夹
Quiet.md            ← 从旧版升级来的文档库（~/Documents/Quiet.md），按文件夹名显示（W5）
  ├ 工作/
  └ 读书笔记.md
quiet-md-notes      ← 用户打开的 git 仓库
  └ …
Obsidian Vault      ← 用户打开的 Obsidian 库
  └ …
本机文件            ← 单个文件，和现在一样
```

和 Codex 的对应：每个顶层文件夹就是一个 project，最初那个只是默认建好的第一个 project。和 Obsidian 的区别：Obsidian 一个窗口一个 vault，我们一个窗口里挂多个顶层文件夹。

## 2. 问题和方案

### 2.1 设置：文件夹级和应用级（W3）

用户 2026-11-22 定的原则：**每个文件夹自包含，包括它自己的设置和废纸篓**。所以设置拆成三类，没有哪个顶层文件夹「装全局设置」：

- **文件夹级**：放在 `<文件夹>/.quiet/`，跟着文件夹走，也跟着同步。凡是和这个文件夹的内容有关的都算。
- **应用级**：只放在本机 `quiet-md/settings/`。只限和这台机器、这个应用本身有关的东西。第一期提供「导出 / 导入设置」（sync.md D5）。
- **本机·按顶层文件夹**：这台设备对某个顶层文件夹的缓存和状态，不是设置，放在本机按文件夹 key 分（`quiet-md/roots/<key>/`）。丢了只损失速度或「最近打开」这类本机信息，不影响文件夹自包含。

现有每一项的归类：

| 现在的位置 | 项 | 归类 | 理由 |
|---|---|---|---|
| `.quiet/index.json` | 置顶、星标、手动排序、文档宽度、阅读模式、目录折叠、属性、引用列表隐藏 | 文件夹级（不变） | 文件夹内容的元数据 |
| `.quiet/trash/`、`.quiet/history/` | 废纸篓、历史版本 | 文件夹级（不变） | 原则里点名的 |
| `.quiet/settings.json` | `scroll_top` 阅读位置 | 文件夹级 | 按文档记 |
| | `history_limit` 每篇保留几个版本 | 文件夹级 | 决定这个文件夹 `.quiet/history/` 的大小，跟着同步也应一致 |
| | `home_manual_initialized` | 文件夹级 | 标记这个顶层文件夹的手动排序已经初始化过 |
| | `home_list`、`home_sort`、`home_folders_first` 主页视图 | 应用级 | 主页是全部顶层文件夹的汇总视图，不属于哪个顶层文件夹 |
| | `sidebar_width`、`quick_note_size`、`refs_hide_no_ask` | 应用级 | 窗口和界面状态 |
| 本机 `libraries/<key>.json`（`Local`） | `window_size`、`window_origin`、`window_display` | 应用级 | 窗口位置 |

| | `opened` 最近打开时间 | 本机·按顶层文件夹 | sync.md 1.5：设备状态，不同步 |
| `.quiet/preferences.json` | `language`/`english`、`appearance`、`motion`、`opaque_window`、`ui_font`、`ui_family`、`font_favorites`、`recent_*_fonts` | 应用级 | 应用界面 |
| | `quick_hotkey`、`auto_update`、`seen_version`、`browser`、`search_engine`、`start_home`、`remote_images` | 应用级 | 这台机器和应用本身的行为（`remote_images` 是本机的联网隐私选择） |

| | `migrate_later`（「稍后」迁移到真实文件夹的时间） | 本机·按顶层文件夹 | 只对某个旧库有意义，是这台设备上的一次选择 |
| | `theme`/`feishu` 文档主题、`doc_family` 文档字体 | **文件夹级（W21 已定）** | 跟着文件夹走；切换到另一个顶层文件夹的文档时外观跟着变，这是有意的。没有设置的顶层文件夹先看它旧的 `.quiet/preferences.json`（从旧版升级来的库保持原样），再用内置默认主题 |
| `.quiet/themes/` | 自定义主题文件 | **文件夹级（W21 已定）** | 就在这个顶层文件夹的 `.quiet/themes/`（旧库本来就在这里） |
| `.quiet/shortcuts.json` | 快捷键 | 应用级 | 按平台不同，sync.md 也这么定 |
| `.quiet/emoji.json` | 最近 / 常用表情、上次选的表情、标注块默认图标 | 应用级 | 个人习惯；文档里用到的表情本身就写在文档里 |
| 本机 | `folders.json` 顶层文件夹列表、解析缓存、恢复副本、锁、同步基准快照 | 应用级 / 本机·按顶层文件夹 | 设备状态 |

**W21（2026-11-22 用户定）**：文档主题、文档字体、自定义主题先放文件夹级。以后另做「文档级的自定义样式」，和全局样式分开；数据结构按「文档 > 顶层文件夹」的覆盖顺序留余地，现在不实现文档级。实现上 `settings::prefs()` 仍是唯一入口，主题和文档字体这三项从当前顶层文件夹（`Store::root_look_at`）叠加上去，保存时写回当前顶层文件夹；`themes::dir()` 指向当前顶层文件夹的 `.quiet/themes/`。

**文件夹级设置怎么存**（和 sync.md 对齐）：不能是各设备都去改写的一个 `.quiet/settings.json`，否则两台设备各改一项，同步盘就会生成 `settings 2.json`，和 `index.json` 的老问题一样。FORMAT 5（sync 1a）里文件夹级设置放进设备元数据的保留条目：`.quiet/meta/<设备id>.json` 的 `items` 里加 `"_root": { "history_limit": [值, 时间戳], … }`，逐字段后写者胜，和置顶、星标走同一套合并。旧库的 `.quiet/settings.json` 在 FORMAT 4 → 5 升级时转进去，原件留给旧版本。第一步（FORMAT 4）仍读写 `.quiet/settings.json`。将来如果主题这类设置成了文件夹级，带文件的（`themes/*.css`）作为普通文件放 `.quiet/themes/`，按内容命名、只增不改。

**升级时的迁移**：新版本第一次启动，`quiet-md/settings/` 还不存在时，从旧文档库的 `.quiet/` **复制**应用级的部分过来（`preferences.json`、`shortcuts.json`、`themes/`、`emoji.json`，以及 `settings.json` 里的应用级字段）。是复制，不是搬：旧版本还要读原来那份，降级不会丢设置。文件夹级的部分本来就在库里，不用动。

**代码**：`Store::internal_dir()` 这组静态函数拆开：应用级用新的 `settings_dir()`（`quiet-md/settings/`，和顶层文件夹无关）；文件夹级的读写走各自 `Store` 的 `.quiet/`。`Store::settings()` 拆成应用级的 `AppSettings` 和文件夹级的 `RootSettings`。

### 2.2 跨文件夹的移动、链接和图片

- **链接**（W6，已定第一步禁掉新建）：
  - 读取：相对路径解析成绝对路径以后，落在哪个打开着的文件夹里就跳到哪里。所以 `../other/x.md` 只要两个顶层文件夹的相对位置没变就能用，VS Code、GitHub 也照样认。
  - 写入：第一步 `@` 链接面板（`src/editor/links.rs`）只列同一个顶层文件夹里的文档，不会新产生跨文件夹链接。第二步允许跨文件夹，仍然写相对路径，插入时提示「这个链接指向另一个文件夹，换一台电脑可能打不开」。
  - 不写绝对路径：换一台电脑、换一个用户名就断，iOS 上也读不到。
  - 解析不到的链接按 real-folders.md 的规则显示成断链，保留文字。断链分两种状态：目标路径落在一个**这台设备上没有打开的顶层文件夹**里（比如 iOS 上指向 Mac 才挂着的文件夹，或者用户刚把那个顶层文件夹移除了），提示「这篇文档在没有打开的文件夹里」；路径在已打开的文件夹里但文件不存在，才按「已删除或移走」提示。判断方法：把相对路径解析成绝对路径后，不在任何已打开的文件夹内就是前一种。
- **移动**（W7，已定）：第一步禁掉跨文件夹拖动，拖到别的顶层文件夹上显示不可放下，提示「暂不支持在文件夹之间移动」。第二步再做真正的移动：在目标文件夹里写文件，带上引用到的图片，把置顶、星标、排序搬到目标顶层文件夹的索引，原件进源顶层文件夹的废纸篓；同一块磁盘上可以直接 rename。移动后改写指向它的链接。
- **图片**：每个顶层文件夹一个 `.assets/`（现状：库根目录下一个，`Store::assets_in`），跨文件夹复制或移动时把用到的图片复制到目标顶层文件夹的 `.assets/` 并改写路径，`transfer.rs` 的导入路径已经在做同样的事。

### 2.3 主页、搜索、回收站、反向引用跨文件夹汇总

- 门面层（第 6 节）的 `list()` 把各个顶层文件夹的条目接在一起，每个 `Entry` 带上它属于哪个顶层文件夹。主页（最近、置顶、星标）、搜索、快速切换、提醒都只消费 `entries`，**第一步就汇总**（W15），每一行加一个灰色的文件夹名（只有一个顶层文件夹时不显示）。主页没有「默认看哪个顶层文件夹」的问题：它本来就是全部顶层文件夹的汇总。
- 回收站：第一步就汇总，因为不再有「默认库的回收站」可以单独显示。每个顶层文件夹都有自己的 `.quiet/trash/`，条目合在一个列表里，每条标出来自哪个顶层文件夹，恢复回原来的顶层文件夹。
- 反向引用：现在按 `Document::doc_links` 在一个库里找。汇总以后在所有顶层文件夹里找，按 2.2 的规则解析路径。第二步做，和跨文件夹链接一起。

### 2.4 顶层文件夹不可用或只读

- **任何顶层文件夹打不开都不致命**（不再有「默认文件夹打不开就退出」）：移动硬盘没插、文件夹被删或改名、没有权限时，侧栏照样显示这一节，标题变灰，下面一行「找不到这个文件夹」，菜单里有「重新查找…」和「从侧栏移除」。`main.rs:163` 那条「无法打开文档库」的致命错误去掉；所有顶层文件夹都打不开时，就是 2.8 的空状态加上几节灰色的顶层文件夹。
- `Store::open_at` 对任何顶层文件夹都不能 `create_dir_all(root)`，否则拔掉的硬盘会在挂载点变成一个空文件夹。只有「新建文件夹」这个动作才建目录。
- 第三步：
  - 只读（没有写权限、只读卷、iCloud 里别人共享的只读文件夹）：打开时试写一次，失败就整个顶层文件夹只读，编辑器只读，侧栏标一个锁。
  - iCloud 占位：交给 sync.md 1.2，顶层文件夹这一层只负责「读的时候不卡住主线程」。
  - 文件夹在别处重新出现（改名、移动）：macOS 记一个书签（bookmark），可以跟着找到；其他平台只能让用户重新选。

### 2.5 往用户的文件夹里写 `.quiet/` 和 `.assets/`

- **每个顶层文件夹都写 `.quiet/`**（W2，用户 2026-11-22 定：「在文件夹里生成 .quiet/ 吧，我觉得这没什么问题，很多产品都有类似处理」）。和 Obsidian 的 `.obsidian/`、VS Code 的 `.vscode/` 一样。`Store` 不需要把内部目录指向别处，`open_at` 照现在的逻辑在根目录下建 `.quiet/`。
- **打开时一句话告诉用户**：打开文件夹成功后，toast 提示「Quiet.md 会在这个文件夹里建一个隐藏的 .quiet 文件夹，存放置顶、排序、历史版本和回收站」，只在这个文件夹第一次被打开时出现（它原来没有 `.quiet/`）。
- **git 仓库**：如果文件夹是 git 仓库（或在仓库里面），上面那句提示加一个按钮「加入 .gitignore」，点了才按 sync.md 2.4 写 `.gitignore` 片段（只忽略本机的部分，元数据照常提交）。不点就不动 `.gitignore`，`.quiet/` 交给用户自己决定提交还是忽略。开了 Quiet.md 的 Git 同步时，由同步线按 2.4 自动写。（和 sync.md 3.6 一致：没开 Git 同步就不自动碰 `.gitignore`。）
- **文件夹里已有别的版本的 `.quiet/`**：按 W11 处理，见 2.6。
- **`.assets/` 照写**：在根目录下，只在第一次粘贴或插入图片时才建。图片是用户的内容，进 git 是对的。Obsidian 库里可以第二步再读 `.obsidian/app.json` 的附件目录设置，按 Obsidian 的位置放（W8）。
- **移除顶层文件夹不删任何东西**：侧栏上去掉，磁盘上的文件夹连同 `.quiet/` 原样不动。以后重新打开同一个文件夹，置顶、历史、回收站都还在。

### 2.6 顶层文件夹嵌套或重叠

打开文件夹时（含拖入、系统「打开方式」），先把路径规范化（`fs_canonicalize`，跟随符号链接），再和每个已打开的顶层文件夹比较（W10）：

- 新文件夹在某个顶层文件夹里面：不新增顶层文件夹，在那个顶层文件夹里展开并选中它，提示「这个文件夹已经在 X 里」。和 `mounts.rs` 现在的行为一样。
- 新文件夹包住了一个或几个已打开的顶层文件夹：拒绝，提示「这个文件夹里已经有打开的 X」，可以先移除 X 再打开。每个顶层文件夹都有自己的 `.quiet/`，外层再建一份，两个索引会管同一批文件。
- 同一个文件夹打开两次：直接跳到已有的那一节。
- 新文件夹自己有 `.quiet/format.json`（另一台电脑上的文档库、以前移除过的顶层文件夹）：直接用它的索引（W11）。格式比当前版本新就拒绝，提示升级；格式旧的走 2.7。

### 2.7 FORMAT 迁移和开始指南

没有默认文件夹以后，这两件事要换一个判断依据。

**FORMAT 迁移**
- 依据改成「这个文件夹是不是一个旧的 Quiet.md 库」（有 `.quiet/format.json` 且版本旧，或者是旧的平铺布局，`migrate::legacy`），和它在侧栏的位置无关。普通文件夹永远不迁移。
- **升级那一次**：新版本第一次启动时，旧版本在用的那个文档库（`library.json` 指向的或缺省位置）按现在的规则处理：`migrate::state` 判断为可以静默迁移就静默迁移，否则征得同意。这只是对「从旧版带过来的那个库」的一次性处理。
- **之后**：打开任何旧格式的 Quiet.md 库，都先征得同意再迁移，沿用 FORMAT 4 迁移时的同意界面。不同意就不打开。
- sync.md 的 FORMAT 4 → 5 同理：每个顶层文件夹各自迁移，按上面的规则判断要不要先征得同意。新打开的、原来没有 `.quiet/` 的文件夹直接按当前 FORMAT 建，不需要迁移。

**开始指南**（W19）
- 写入时机：**引导页上选「新建文件夹」、新建出来的文件夹是空的**时，把指南写进去，和现在「空库才写」的效果一样。选「打开已有的文件夹」的不写，用户自己的文件夹里不该凭空多出几篇文档。
- 后来想看指南：「帮助 › 开始指南」，把指南写进一个新建的顶层文件夹「Quiet.md 开始指南」（位置默认在 `~/Documents/`，可改），挂到侧栏上。看完可以直接移除这个顶层文件夹。空状态（2.8）上也有这个入口。
- `guides::seeded` 里「空库」的判断不变，只是调用点从「打开默认库时」改成「新建文件夹时」和「帮助菜单」。

### 2.8 一个顶层文件夹都没有

两种情况会走到这里：用户把所有顶层文件夹都移除了；首次启动时引导页被跳过，或者选了「打开已有的文件夹」又取消了。

- **空状态**：侧栏只有「主页」和底部的设置，主区域显示一个居中的空状态，三个按钮：「打开文件夹…」「新建文件夹…」「查看开始指南」。拖文件夹到窗口任何地方也能打开。
- **需要一个顶层文件夹才能做的操作**：
  - 新建文档（⌘N）、快速笔记、导入：弹出同样的空状态面板，先选或建一个文件夹，完成后接着做原来的操作。
  - 打开单个文件（「本机文件」）不需要顶层文件夹，照常工作。
- **快速笔记存到哪**：设置里加一项「快速笔记保存到」，选一个顶层文件夹，默认是侧栏第一个可用的顶层文件夹。选中的顶层文件夹被移除或不可用时，退回到第一个可用的顶层文件夹；一个都没有就走上面的空状态面板。
- **新建文档（⌘N）存到哪**：当前选中的文件夹或打开的文档所在的顶层文件夹，没有就用侧栏第一个可用的顶层文件夹。
- 应用本身不依赖任何顶层文件夹就能启动：设置、主题、快捷键都在本机（2.1），`SharedStore` 允许空列表。

### 2.10 多台电脑

- **顶层文件夹能不能跨设备看到**（显示用，不影响功能）：每个顶层文件夹算一个「可达性」，在顶层文件夹的菜单和设置的文件夹列表里显示：
  - 只在这台电脑：普通本机文件夹；
  - 在同步盘里：路径落在 iCloud 云盘、`~/Library/CloudStorage` 下的第三方 File Provider（`migrate::sync_of` 已能识别），文件会到别的设备，但别的设备要自己打开这个文件夹才会出现在侧栏；
  - Quiet.md 同步：这个顶层文件夹开了 sync.md 的 iCloud 或 Git 同步。
- 顶层文件夹列表是本机的（W13），和 Codex 的 project 列表一样，A 电脑打开的文件夹不会出现在 B 电脑上。路径在不同电脑上本来就不一样。
- 想在两台电脑上用同一批笔记：把那个顶层文件夹放在同步盘（或者以后的 iCloud 容器，W17）里，再在另一台电脑上打开它。引导页上「新建文件夹」的默认位置决定了大多数人的第一个顶层文件夹在哪，所以 W17 仍然要定。
- 一个顶层文件夹自己在 iCloud 里、另一个顶层文件夹是 git 仓库：每个顶层文件夹各自开各自的同步方式，互不影响（sync.md 的 D13「同一个库不能同时开 iCloud 和 Git」按顶层文件夹判断）。
- 设置不跟着任何顶层文件夹走（2.1）。跨设备同步设置是同步线的事。

### 2.11 顶层文件夹的名字和重命名（W5）

- **顶层文件夹显示的名字就是文件夹名**，不另存显示名（用户 2026-11-22：「顶层文件夹的显示名就是文档名可以吗？」，这里的「文档名」理解为文件夹名）。准确说是系统给这个文件夹的显示名（macOS `URL.localizedName` / `NSFileManager.displayName(atPath:)`，其他平台就是文件夹名），普通文件夹两者一样；只有 App 的 iCloud 容器这类系统特殊文件夹不同，见下面 iOS 一条。
- **代价**：从旧版升级上来的库叫 `~/Documents/Quiet.md`，侧栏这一节显示「Quiet.md」，不再是「我的文档」；面包屑起点也跟着变。这是老用户唯一会看到的界面变化，在更新日志里写一句。引导页新建的文件夹默认名仍是「Quiet.md」（W17 的位置不影响名字）。
- **在侧栏里重命名一个顶层文件夹，就是改磁盘上的文件夹名**：
  - 做法：先停掉这个顶层文件夹的文件监听和形状比较、刷掉待写入的保存（`flush_view_state`、编辑器的待保存内容），`vfs::rename(旧路径, 同目录下的新名字)`，成功后把 `Store` 的根目录换成新路径，更新 `folders.json` 的 `path`（macOS 顺便刷新 `bookmark`），再恢复监听。打开着的文档不用重开：门面层的 id 前缀用的是稳定的文件夹 key（见下一条），不随路径变。
  - **文件夹 key 不能再由路径算出**（原计划沿用 `library_key(path)`）：改名会让 key 变掉，锁、基准快照（`quiet-md/sync/<key>/`）、解析缓存、恢复目录全都对不上，打开着的文档 id 也会变。改成 `folders.json` 里每一项一个随机 UUID，添加顶层文件夹时生成，改名、移动都不变。升级时已有的按 `library_key` 命名的本机数据（解析缓存、恢复副本）在生成 `folders.json` 时按新 key 改名一次；解析缓存丢了也只是慢一次。
  - 文件名规则：和文档、文件夹改名用同一套（`file_name_for`：替换非法字符、去掉开头的点、Windows 保留名加下划线）。
  - **改名失败时**，名字退回原样，toast 说明原因：
    - 同一个上级目录里已有同名的文件或文件夹：「已经有一个叫 X 的文件夹」；
    - 没有权限、只读卷：「没有权限给这个文件夹改名」；
    - 被占用（Windows 上别的程序开着里面的文件，`ERROR_SHARING_VIOLATION`）：「文件夹正在被其他程序使用，关掉后再试」；
    - 顶层文件夹不可用（2.4）：菜单里的重命名是灰的；
    - 用户的主目录、桌面、文稿这类系统文件夹，以及 iCloud 容器：不提供重命名。
  - **对同步的影响**：
    - Git：`.git/` 在文件夹里面，跟着一起改名，仓库不受影响；remote 也不受影响。顶层文件夹如果是仓库的子目录，git 里会看到一次整目录的 rename，下次自动提交时带上。
    - iCloud 云盘里的顶层文件夹：相当于在 iCloud 里改名，会同步到别的设备。别的设备上 `folders.json` 记的还是旧路径：macOS 靠 `bookmark` 能跟着找到新位置并自动更新；找不到就显示成「找不到这个文件夹」（2.4），用户选「重新查找…」。
    - 其他同步盘（Dropbox、坚果云……）同 iCloud，靠 `bookmark` 跟踪，跟不上就手动重新查找。
  - 在访达里改了顶层文件夹的名字：下次启动或窗口激活时，macOS 按 `bookmark` 找到新路径，静默更新 `folders.json`，侧栏标题跟着变；其他平台显示「找不到」，手动重新查找。
- **iOS 的 iCloud 容器**（和移动端对齐中，W20）：容器路径末尾是 `Documents`，但系统给它的显示名就是 App 名「Quiet.md」（文件 App 和访达里看到的都是这个），所以按上面「系统显示名」的规则直接显示「Quiet.md」，不用另建一层文件夹，也不用特殊处理。容器不能改名，菜单里不提供重命名。

## 3. 界面

> 第一步的实现（2026-11-22）：顶层文件夹在侧栏里不是各自一节，而是同一棵树的顶层行（两个及以上时，标题为「文件夹」）；只有一个顶层文件夹时外观不变，标题换成文件夹名。现有的拖拽和动画围绕一个行列表实现，拆成多个列表改动太大。顶层文件夹的行由门面层合成（`shared_store::top_row`），交给各顶层文件夹的 `Store` 时还原成它自己的顶层（`None`）。

- **侧栏**：顶层一节一个顶层文件夹，顺序可拖动调整。节标题右侧悬停出 `…` 菜单：在访达中显示、新建文档、新建文件夹、重命名（就是改磁盘上的文件夹名，2.11）、以后的同步设置、从侧栏移除。每个顶层文件夹都能移除，移除时确认一次：「只是从侧栏去掉，文件夹里的文件不会删除。」节标题可以接收拖入的文件和文件夹。
- **新建文件夹…**（文件菜单和空状态）：在选定位置建一个空文件夹（有 `.quiet/`），挂到侧栏上。
- **打开文件夹**：保留现有入口（文件 › 打开文件夹…、⌘⇧O、拖到侧栏或窗口、系统「打开方式」），结果从「挂在本机文件下」改成「侧栏多一节」。
- **引导页**（W12，已定）：第一页「你的笔记放在哪」，主按钮「打开文件夹…」，旁边是「新建文件夹」（默认位置见 W17，可更改）。第二页发现的 Obsidian、Logseq 等文件夹，默认按钮是「打开」（原地挂进侧栏），「导入一份副本」作为次要选项保留。都不选也能跳过，进入 2.8 的空状态。
- **空状态**：见 2.8。

## 4. 和其他几条线的接口

**同步（sync.md）**
- 每个顶层文件夹是一个独立的 `Store`，同步也按顶层文件夹开：每个顶层文件夹自己的 `.quiet/meta/<设备id>.json`、自己的同步方式。设备 id 全局一份，所有顶层文件夹共用。
- 本机锁 `quiet-md/locks/<文件夹 key>.lock` 按顶层文件夹各一把，基准快照 `quiet-md/sync/<文件夹 key>/` 也按顶层文件夹分。**文件夹 key 是 `folders.json` 里每一项的随机 UUID**，不再由路径算出，顶层文件夹改名或移动后不变（2.11）。
- 每个顶层文件夹都有 `.quiet/`，元数据就在文件夹里，同步开着就跟着 iCloud 或 Git 走，**开同步不需要迁移或升级**（原来的「同步文件 / 同步元数据」两层和 sync.md D17 作废）。放在 iCloud 云盘里的顶层文件夹，不管开不开 Quiet.md 的同步，iCloud 都在同步它的文件，所以占位文件、冲突副本识别、文件监听、基准快照、三方合并对每个顶层文件夹照常生效。
- sync.md 3.3 里「外部文件的 id = 相对路径的哈希」只在一个顶层文件夹里唯一，两个顶层文件夹都有 `Notes.md` 时会撞。文件夹里面照这么做没问题，跨文件夹的唯一性由门面层负责（W14）。**文件夹 key 前缀只出现在内存和门面层，从不写进文件夹里的文件**：设备元数据、索引、链接里存的都是文件夹内 id。文件夹 key 是每台设备自己生成的随机 UUID（2.11），同一个顶层文件夹在两台电脑上 key 不同，写盘就对不上。文件夹 key 只用来给本机数据命名（锁、基准快照、解析缓存、恢复目录）。
- **先后**（sync.md 3.6）：顶层文件夹第一步和 sync 的 1a 都要改 `Store::internal()` 那一片。顶层文件夹第一步先合，1a 在它之上直接按「每个顶层文件夹一份元数据」写。
- **设置（D5）**：文件夹级设置在各顶层文件夹的 `.quiet/` 里，随文件夹同步；应用级设置在本机 `quiet-md/settings/`，sync.md D5 第一期不同步，提供「导出 / 导入设置」。以后要同步应用级设置，前提是不重新引入特殊顶层文件夹（D5 的 B：任意一个顶层文件夹上勾选「应用设置跟着这个顶层文件夹同步」，最多一个，可随时取消）。
- `library.json` 不再是「库在哪」的来源（2.9）。D12 的 iCloud 容器只是顶层文件夹可能放的一个位置，引导页「新建文件夹」的默认位置见 W17。

**移动端（mobile.md）**
- M5（iOS 的库放 iCloud 容器，打开其他文件夹放第二版）和本方案一致，措辞改为：**iOS 第一版的主页固定只有一个顶层文件夹，就是 iCloud 容器里的那个文件夹**（没登录 iCloud 时是沙盒里的）。它在 iOS 上不提供移除，因为第一版没有别的顶层文件夹可以加；这是 iOS 第一版的产品范围，不是这个顶层文件夹有特殊地位。
- 第二版添加顶层文件夹时，iOS 上要存带安全作用域的书签，`folders.json` 的每一项预留 `bookmark` 字段（macOS 上也可以用来跟踪被改名的文件夹，见 2.4）。
- 移动端直接用同一个门面，只是列表里只有一项，不需要另写一套单库代码。
- iOS 上文件夹级设置随文件夹（在容器里）走，应用级设置放 App 沙盒。

**#357 子文档**（规则见 s1dashu/quiet-md#360 的 FORMAT.md「Child pages: a folder's own document」：`X/X.xml` 或 `X/X.md` 是文件夹 `X/` 的正文）
- 子文档逻辑只需要在 `Store` 里实现一次，所有顶层文件夹自动都有。现在 `note_shape` 排除了 `local()` 条目，所以本机文件夹里的 `X/X.md` 不认；本机文件夹升级成顶层文件夹以后，它们是顶层文件夹自己 `Store` 里的普通条目，不再是 `local()`，这条限制自然消失，不用单独放开。
- 外部文件夹（Obsidian 库、git 仓库）里原有的 `X/X.md` 也会按这个约定显示，默认套用，见 W18。
- 顶层文件夹本身没有父目录，永远不是谁的正文：`顶层文件夹/顶层文件夹.md` 是顶层文件夹下面的普通文档。侧栏的顶层文件夹节标题因此没有「正文」可打开，点击只折叠。本机文件夹那条单独的代码路径（`create_in_mount`、`move_in_mount`）第一步就会删掉，不用给它补子文档。

**CLI（`feat-cli`）**
- 路径从主页算起，第一段是顶层文件夹名（不分大小写，也可以用 key 或磁盘上的绝对路径）；没有专门挑顶层文件夹的参数。见 docs/design/CLI.md。
