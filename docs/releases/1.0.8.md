# Fei Notes 1.0.8 beta

Mac and iOS share one immutable source release, `feinotes/v1.0.8`. The existing
`feinotes/v1.0.7` tag remains unchanged. Cargo package versions continue to identify
the merged Quiet.md source; the Apple bundle version is independently 1.0.8.

## Changes since 1.0.7

- Integrate the native iPhone/iPad app with current original-note and shared-folder
  semantics, cloud checkpoints, offline merging and attachment retention.
- Preserve checkpoint retention metadata on repeated receipt after a cursor reset.
- Bound the mobile board frame cache and keep original-note organization in its
  current library scope.
- Correct the iOS system-font platform branch so Chinese and English headings and
  inline bold retain their requested weight in the Notes theme.
- Accept Apple's provisioning-profile permission allowlists while still requiring
  the signed app to select Production, the exact container and CloudKit service.
- Preserve the approved bilingual website visual design. Keep editable demo
  documents locally, use native app captures, and loop the Notes sync and Feishu
  real-time editing demonstrations with pause and reduced-motion support.

## Distribution

Use the same final source commit for both platform workflows. Each platform gets
its own unused Apple build number and processing/review receipt. The release task
owns both uploads; source and website commits use `[skip ci]` to prevent a duplicate
automatic Apple run. Dispatch the website separately from the exact approved source.
The homepage continues to reflect actual Apple availability, including the older
approved build while the new version is pending review.

Mac TestFlight notes: `docs/releases/1.0.8/macos/`.
iOS TestFlight notes: `packaging/ios/release-notes/1.0.8/`.

## Verification boundaries

Repository ordinary and CloudKit checks, native iPhone Chinese/English captures,
release-profile tests, website lifecycle tests and desktop/narrow visual checks
are local evidence. They do not establish a signed upload, Apple review approval,
physical Intel support or real multi-account acceptance. The release workflow
checks its exact selected source again before distribution.
