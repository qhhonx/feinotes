# Whiteboards: porting Excalidraw to Rust

Implemented on 2026-11-14, with styling aligned to Excalidraw on November 15. This supersedes the unreleased Feishu-inspired prototype on `feat/whiteboard`. This design records the implementation and gaps at that point. Consult the code and file headers for details, and the [benchmark history](../../tools/perf/board-results.md) for subsequent renderer changes.

## Design decisions

- Port interactions, data structures and algorithms module by module from Excalidraw.
- Match Excalidraw's styling throughout. The November 15 decision superseded the earlier plan to use application Theme tokens and omit sketch rendering. The canvas uses the rough.js port with each element's `roughness` and `seed`, bundled Excalidraw fonts and the upstream dark-mode filter. Toolbars, panels, menus and selection handles use upstream CSS values and icons.
- Exclude tldraw as a reference because its license is proprietary.
- Store Excalidraw element JSON. The November 14 decision excludes migration of prototype board data.
- Models, geometry, algorithms and undo live in GPUI-independent `crates/core/src/board/`. Tool state machines, rendering and chrome live in `src/board/`, which re-exports core modules so paths such as `crate::board::scene` refer to core.

## Upstream baseline

The port pins the MIT-licensed Excalidraw 0.18.0 source at `3a317b55f508815d10a4c12acca99df30f026521` (2026-11-14). Follow future upstream diffs file by file. Each ported Rust file identifies its upstream counterpart and deviations. [Third-party notices](../../THIRD_PARTY.md) cover Excalidraw, rough.js 4.6.4, hachure-fill, points-on-curve, points-on-path, path-data-parser, perfect-freehand, fractional-indexing and nanoid.

## Rendering

Core's `display.rs` emits a backend-independent display list of paths, fills, strokes, text and images.

1. **GPUI**, all platforms (`src/board/render.rs`). Draws the display list with `PathBuilder`, text and images. Cache each element's display list until its `version` or `versionNonce` changes, and cache tessellated paths in quarter-octave zoom buckets. Pan, zoom and hover reuse paint order and bounds, culling by bounds. GPUI supports axis-aligned rectangular clips and cannot rotate text or images directly. Draw rotated text as SVG images, resample rotated/flipped/cropped/frame-clipped images on CPU, and clip paths by triangle for frames and arrow-label cutouts (`render_geom.rs`).
2. **vello_cpu** (`src/board/render_vello.rs`). The cross-platform implementation described here switched at 800 visible elements and returned to GPUI below 500, with thumbnails switching at 64. It rasterized into a pixmap, converted to BGRA and copied into a rotating set of three `PixelFrame` buffers for `Window::paint_pixels` (legacy patch 36). GPUI lays out text and vello draws outlines from CoreText, DirectWrite or swash (legacy patch 37). Color emoji have no outline and are omitted. Reuse the last frame while scene, view and theme stay unchanged.

See [benchmarks](../../tools/perf/board-results.md) for thresholds and measurements by build. Selection boxes, handles, snap guides, text editors, toolbars and panels are native GPUI elements over the content (`overlay.rs`, corresponding to upstream `interactiveScene`).

The line-by-line rough.js 4.6.4 port in `crates/core/src/board/rough/` includes the generator, renderer, all fill styles and seeded random stream, preserving draw order for random values. `shape.rs` ports `generateRoughOptions` and related logic from `shape.ts`. `crates/core/tests/board_rough.rs` compares 86 real rough.js outputs to a tolerance of 1e-6 using `fixtures/board/rough.json` generated by the adjacent `rough_gen.cjs`.

`color.rs` ports `applyDarkModeFilter` as `apply_dark_mode_filter`, equivalent per color to `invert(93%) hue-rotate(180deg)`. It filters the canvas background and element colors. Items upstream leaves unfiltered, such as sticky note shadows, use `display::theme_color`.

## Storage

- **Embedded boards.** The body of `<whiteboard type="excalidraw" height="…">` holds scene JSON: `{"elements":[…],"files":{…}}`. Images live in `.assets`. The files map stores IDs, paths and MIME types without inline data URLs. The writer sorts elements by fractional `index`, emits one per line, orders keys as declared in upstream `types.ts` and preserves unknown keys at the end. The canonical example in `all-blocks.xml` round-trips exactly. See [Storage format](../FORMAT.md).
- **Standalone boards.** `.excalidraw` uses official JSON fields `type`, `version`, `source`, `elements`, `appState` and `files` and opens on excalidraw.com. `DocKind::Board` uses the `excalidraw` extension. Older versions skip unknown extensions so `store::FORMAT` needs no increment.
- Persist only file-level `appState`: `viewBackgroundColor`, `gridSize`, `gridStep` and `gridModeEnabled`. Viewport, selection and tools remain transient, following `cleanAppStateForExport`.
- Read through `restore.rs` (from `data/restore.ts`) to supply defaults and repair old fields, bindings and fractional indices. `encode.rs` also reads scenes embedded in PNG and SVG.

## Document integration

- **Blocks.** `BlockKind::Board(Arc<Board>)` has a static, element-version-cached thumbnail in documents and home cards (`src/editor/board.rs`). Skip drawing it when the board is open. Double-click or choose Edit to replace the document with the board in the note area. The app top bar and sidebar stay accessible. The breadcrumb ends with “Document › Board”, and clicking the document returns to it. The slash and + menus insert and open an empty board. Standalone boards open directly with the usual note top bar. Use New › Board in the sidebar or folder page to create one.
- **Undo.** Board editing uses incremental undo ported from `store.ts` and `delta.ts` (`history.rs`). Edits write back to the block via `Core::set_board` and form one document undo step per board session. Pan and zoom bypass store commits and scene snapshot comparisons.
- **Fuzzing.** A random operation replaces a Board block's scene. Invariants require it to survive saving and reloading.
- **Search.** `plain_text` includes text elements' `originalText` and frame names.
- **Export.** Markdown export with attachments emits an SVG (`export_svg.rs`, modeled on `staticSvgScene`) and an `.excalidraw` file. HTML, PDF and print embed SVG.
- **Clipboard.** `excalidraw/clipboard` JSON works in both directions with excalidraw.com. Paste accepts text, HTML, images and scenes embedded in PNG/SVG. Copy as PNG/SVG embeds the scene so pasting it back restores editable elements. Upstream clipboard image copying omits the scene.

## Text

- Preserve `fontFamily` IDs 1–10. Draw and measure using bundled fonts in `assets/fonts/excalidraw/`: Excalifont, Virgil, Nunito, Lilita One, Cascadia, Comic Shanns, Assistant and Xiaolai for Chinese. Upstream WOFF2 subsets are merged into TTF. Xiaolai is zlib-compressed and registered on first use. See THIRD_PARTY.md for licenses.
- Following upstream CSS, `src/board/fonts.rs` splits each line into font runs. Missing CJK characters fall back to Xiaolai, then other missing characters such as emoji to system fonts. Baselines follow `getVerticalOffset` and per-font metrics in `text_measure.rs`.
- Use metrically compatible Arial for Liberation Sans (9), whose upstream version uses GPL with a font exception. Helvetica (2) uses the system font.
- Core defines the `Measure` trait. The app implements it with GPUI's `TextSystem::layout_line`. Core tests use the upstream mock of 10 px per UTF-16 unit.
- Wrapping, bound text, automatic sizing and adaptive sticky note font sizes follow `textWrapping.ts`, `textElement.ts` and `stickyNote.ts`.

## Interface

- The centered top toolbar follows Excalidraw: lock, pan H, selection V/1, rectangle R/2, diamond D/3, ellipse O/4, arrow A/5, line L/6, freehand P/7, text T/8, sticky note N, eraser E/0, image 9, frame F and lasso. The left property panel appears for a selection or active tool. Zoom and undo sit at bottom left and help at bottom right. Context menus and shortcuts follow upstream `shortcuts.ts`. Board shortcuts take priority while open, leaving window shortcuts such as ⌘W and ⌘Q available.
- `chrome/style.rs` records light/dark colors, shadows, radii, button sizes, spacing and type sizes from upstream `theme.scss`, `variables.module.scss` and `styles.scss`. The UI uses Assistant with browser-equivalent normal line height (`style::lh`). The main menu includes canvas background. The picker includes common and frequently used scene colors, palette shortcuts, shades and hex input. The font list supports search, hover preview and arrows. The context menu includes text binding, copy as text, arrow binding and midpoint snapping. Hints, more tools and clear-canvas confirmation follow upstream. Properties include stroke roughness.
- The board uses 96 icons in `assets/icons/excalidraw/` from upstream `icons.tsx` (MIT, mostly from tabler-icons). Each SVG credits its source. Nucleo icons are separate.
- UI strings use Chinese translation keys and English fallback.

## Differences from upstream

File headers explain the individual decisions.

- **Randomness.** rough.js uses `Math.random()` for a zero seed and dotted fills. Use a deterministic stream for stable rendering.
- **Sticky notes.** Draw a 0.5 px inside outline in place of upstream's clipped 1 px stroke.
- **Dark mode.** SVG images keep their colors because the image path cannot apply per-pixel filters. SVG exports use light colors.
- **Fonts.** Substitute Arial for Liberation Sans. Export SVG with embedded TTF subsets (upstream uses WOFF2). Copy as PNG may use PingFang for Chinese.
- **Interface.** Omit collaboration, libraries, AI, social links, statistics, zen/read-only modes, minimap, pen mode, laser pointer, embeds, bucket fill, command palette and canvas search. The lower left shows the upstream minus/zoom/plus controls with minimap disabled. The main menu omits open/save/export/find/theme. Color pickers omit the eyedropper, arrow/Tab navigation and drag-to-favorites. Fonts cannot be dragged to favorite slots. Pen pressure toggles, link buttons, link dialogs and element link icons are absent. Toolbar tooltips are drawn with a black background in place of browser-native titles. The board sits under the app bar, so the upper-left menu has no filename. Return through the breadcrumb or press Esc with nothing selected. Chinese labels distinguish Copy from Duplicate and Line from Hachure.
- **Frames.** Border width and radius use scene units (upstream divides by zoom on the interactive canvas). Frame text clips to frame bounds. Frame names draw above the canvas at a fixed 14 screen pixels as upstream (`frame_name.rs`), and in scene units for thumbnails and exports.
- **Undo.** Apply deltas in element-ID order (upstream uses insertion order). Compare values deeply (upstream compares one level of references). Treat JSON null and absent values alike (`history.rs`).
- **Clipboard.** Copy as PNG/SVG embeds the scene. Paste unrecognized SVG source as text because the image renderer cannot display SVG. Upstream inserts it as an image. Table-to-chart and Mermaid paste are unsupported (`clipboard.rs`).
- **Freehand.** Constant-width strokes use perfect-freehand in place of `@excalidraw/laser-pointer` (`shape.rs`).
- **State.** Omit collaboration, dialog, export dialog, theme and pen-input fields from `appState`. Keep `boxSelectionMode` at its default (`app_state.rs`).
- **Vello.** Color emoji are omitted.

## Work outstanding in the original design

- Upstream library panel, collaboration, element links and dialogs, web embeds (`embeddable`), bucket fill, freehand-to-shape (`convertToShape`), laser pointer, Mermaid/text-to-chart, command palette, search, minimap, statistics and export dialog.
- Paste board clipboard JSON into document text as a Board block.
- The original list included Windows/Linux vello texture paths and clipping rotated text in GPUI. The [renderer report](../../tools/perf/board-results.md) records subsequent cross-platform backend work.

## Acceptance checks

- **Algorithms.** Port applicable tests from upstream `packages/math/tests`, `packages/element/tests` and `excalidraw/tests` to `crates/core/tests/board_*.rs` and `board_transform/` with identical inputs and expected values. File headers list omitted cases and reasons, typically React/DOM interactions, spy counts or features not ported.
- **Format.** Read, write and reread the `.excalidraw` fixtures in `crates/core/tests/fixtures/board/`. Round-trip `all-blocks.xml` and the guide library.
- **Routine checks.** Run `scripts/check.sh` with zero warnings and `FDL_FUZZ_SEEDS=2000 cargo test --release random_edits`.
- **Performance.** In the `board_gen.py` scene with 10,000 shapes (~32,500 elements), overview panning was about 12 ms per frame, 100% panning about 3 ms and handling ⌘= / ⌘- about 0.02 ms. See [benchmark results](../../tools/perf/board-results.md).
